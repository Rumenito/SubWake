# Architecture

How the app is put together and where to make a change. Back to the [README](../README.md).

## Stack

- **Language and UI:** C# on .NET 10 Windows Forms (`net10.0-windows`, x64, PerMonitorV2 DPI), with an HTML/CSS/JS window hosted in **WebView2** (`Microsoft.Web.WebView2` 1.0.4258.31).
- **Packaging:** published self-contained with ReadyToRun, then packaged with **Inno Setup 6**.
- **Audio:** Windows Core Audio COM interfaces, declared by hand with `[ComImport]`: WASAPI shared mode for playback, peak meters and audio sessions for detection. No audio packages.
- **Tests:** a small console project, `Source/Tests`, run by the build. No test packages.

## Runtime flow

1. `Program.Main` handles `--stop` and `--configure-startup=`. Otherwise it takes the mutex, or signals the running copy and exits.
2. `SubWakeApp` loads settings and the activity history (from the log), creates the tray icon, subscribes to `SystemEvents.SessionSwitch` and `PowerModeChanged`, starts the `AudioMonitor` thread, logs "Started…", and starts the timer. Without `--startup`, it also opens the window.
3. **Every tick (1 s), on the UI thread:**
   - Check the stop and show events, and the quit flag.
   - Take a snapshot of the monitor (`MonitorState`), and save the output's ID or new name if it changed.
   - Every 5th tick, check which hold apps are running.
   - Apply any pending unlock or wake burst time, then work out away (and a return).
   - If wait-for-silence is on, push the next burst to at least *last signal + interval*, and log audio start/stop.
   - End an expired snooze. Work out the pause reason with `Rules.PauseReason` and log changes.
   - Run either the calibration step or the scheduled burst.
   - Update the tray.
   - Every 2nd tick, push state to the window.
4. **`Burst()`:**
   - Snapshots the settings and tones, and tells the monitor its own playback is starting.
   - On a worker (`Task.Run`), `AudioOut.Play` finds the output by ID or name, opens a shared-mode `IAudioClient` at the output's mix format, synthesises the samples at that rate and plays, blocking until the buffer has drained.
   - Back on the UI thread (thanks to `WindowsFormsSynchronizationContext`), it records the result or the `PlaybackProblem`, updates the `Scheduler`, adds to the history and pushes state.
5. **SystemEvents handlers** run on other threads. They only set `volatile bool locked` and an `Interlocked` tick value, which the next tick reads.
6. **`AudioMonitor`** runs on its own MTA background thread. It owns every Core Audio object it opens. It shares only `Interlocked` last-signal and last-sound times, and a locked snapshot (devices, target, watched and active outputs, recording apps, levels, error).
7. **The window:**
   - Is created on demand, at its saved position if that's still on a screen.
   - Maps `https://subwake.local/` to `<app>\ui`.
   - Sends `ready`, then exchanges JSON messages ([protocol](STATE-AND-PROTOCOL.md#window-messages)). A 250 ms timer sends level-bar updates while it's open.
   - Saves its bounds and is disposed on close.
8. **Exit:** stops the timers, unsubscribes events, stops the monitor thread, logs "Stopped.", closes the window and removes the tray icon.

## Audio engine

- **Playback:** WASAPI shared mode, mixed with other audio. It uses the output's mix format when that's 32-bit float or 16-bit PCM. Otherwise it hands Windows float stereo with automatic conversion. Buffer 200 ms, filled first, then topped up every 15 ms. It times out at burst length + 5 s.
- **Synthesis:** at the output's sample rate, one channel copied to every channel. Each low tone (the main tone at `lowToneHz`, and 20 Hz) plays at the set level and the 20 kHz tone at −40 dBFS. They are summed and scaled down only if the sum would pass −0.1 dBFS (`MaxPeak`). A raised-cosine fade (0.2 s) at each end, so it never clicks or clips.
- **Finding the output:** `Devices.Resolve` tries the endpoint ID, then the exact name, then a name containing the saved one (this covers 1.0.x names cut to 31 characters by the old waveOut API).
- **Errors:** `AUDCLNT_E_DEVICE_IN_USE` and `EXCLUSIVE_MODE_ONLY` → Busy. `DEVICE_INVALIDATED` and "element not found" → Missing. Anything else → Failed, with the error code.

## Audio detection

- **Outputs:** `IMMDeviceEnumerator` → active render endpoints → `IAudioMeterInformation.GetPeakValue`, every 50 ms. Grouping uses the last "(…" part of the burst output's name.
- **Threshold:** a reading at or above `signalThresholdDb` is "signal" (holds bursts, lights chips, resets the sub timer). Above −70 dBFS is "sound" (away, calibration).
- **Own sound:** during a burst and 0.5 s after, the burst output is read through `IAudioSessionManager2` instead: the loudest session of any other process. Other outputs are unaffected.
- **Recording:** every second, the session lists of every active capture endpoint. Any session in the active state from another process counts. Names come from the file description, else the process name, cached by process ID.
- **Device changes:** an `IMMNotificationClient` flags a refresh on add, remove, state change or rename. There's also a fallback re-scan every 60 s, or every 5 s if registration failed. Any COM error is shown in the window, and the schedule runs without the hold.
- **Meter domain:** the meter reads the stream Windows sends to the endpoint. Audio sent through ASIO, or the interface's own inputs, is invisible to it.

## Key decisions

| Decision | Why |
|---|---|
| Periodic burst, not a constant tone | A sub needs signal only once per standby time (often 15 min). Short bursts are inaudible and leave the output free. |
| 35 Hz default, other frequencies, 20 Hz and 20 kHz optional | 35 Hz is inside most subs' range and below what's easily heard. Subs differ in what they sense, so the frequency is a choice. 20 Hz and 20 kHz are fallbacks with unknown benefit. |
| WASAPI shared mode, output saved by endpoint ID | Full names, survives renames, same device list as the meter, and the app's own session can be told apart from music. Replaced waveOut in 1.1.0. |
| Low tones share the volume as a peak | Two tones at the same level used to add up and clip. The slider now means the real peak. |
| Tick-counter schedule clock | Daylight saving and time syncs can't delay a burst. Only quiet hours need local time. |
| Rules in pure classes, tested at build time | The schedule is the core of the app. A failing rule stops the build before an installer is made. |
| WinForms host + WebView2 page | A native tray and lifetime, with a styled HTML UI. The window is disposable, so memory stays small. |
| One UI-thread timer | No locks around app state. Cross-thread data is two system-event fields and the monitor's snapshot. |
| Atomic settings write (`.tmp` then move) | A crash or power loss never leaves a half-written file. |
| HKCU Run value, not a Startup-folder shortcut | Per user, no admin, and easy for the uninstaller to remove. It replaced the PowerShell version's shortcut. |
| Wait for silence on the device's outputs by default, or a chosen list | On the original setup every CONNECT 6 output was routed to the sub, so any of them carrying audio keeps it awake. Other setups differ (headphones on the same device), so the list can be chosen. A burst during music would only intrude. |
| First-run setup, no assumed output | A public release can't guess which output feeds the sub. Nothing plays until the user picks one, which also keeps the first burst at a level they chose. |
| Update check only notifies | Opening the release page keeps the user in control and needs no updater. It's the only network request, can be turned off in Setup and the app, and is described in the installer (SignPath Foundation rules). |
| Threshold −50 dBFS by default, set from calibration | Very quiet audio may not keep the sub awake. Counting it would hold bursts while the sub sleeps. |
| Holds for recording and named apps | A burst can bleed into a room mic. A DAW on ASIO is invisible to the meters. |
| Away lets the sub sleep | Bursts all night with nobody there only wear the sub. The first touch wakes it. |
| Calibration only suggests | The user wants a fixed level they chose themselves. The stored result only draws marks and offers **Match calibration**. |
| Self-contained publish | Installs on a clean PC without a .NET runtime. |
